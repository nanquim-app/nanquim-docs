# Usuários

Perfis iniciais, com o trabalho que cada um precisa fazer. Nenhum deles foi entrevistado formalmente ainda: a fonte é o uso interno e as conversas de construção do produto. Entrevistas são um pré-requisito antes de validar hipóteses de adoção.

| Perfil | Hoje usa | Trabalho a fazer | O que o Trunkpad muda |
|---|---|---|---|
| **Fundador / Head de produto** | Obsidian + Claude Desktop + Claude Code | Planejar, decidir, revisar o trabalho dos outros, manter padrão de documentação | Uma ferramenta só; revisão com diff; agentes e personas do repositório |
| **Analista / PM de growth** | Obsidian, Metabase, planilhas | Escrever hipóteses e análises, rodar queries, atualizar painéis | Scripts e conectores permitidos no lugar de copiar e colar; checkpoints do agente |
| **Líder de operação** | Notion, Google Docs, WhatsApp | Manter processos, réguas e tabelas atualizados | Editar planilhas e páginas com o agente, sem perder histórico |
| **Revisor (diretor, CFO)** | E-mail, PDF, comentários no Docs | Aprovar propostas e números | Inbox de propostas com diff renderizado e comentários ancorados; aprova sem aprender git |
| **Engenheiro** | Cursor, Claude Code, GitHub | Reusar o que o negócio escreveu; manter skills e scripts | Mesmo repositório; nada a instalar além do que já usa |

## Momentos da jornada

1. **Primeiro uso:** abre uma pasta (um vault do Obsidian serve como está), configura nome, e-mail e chave de API. Sucesso = primeira versão salva.
2. **Primeira rodada com o agente:** pede algo concreto, vê os arquivos mudarem no palco, revisa e incorpora. Sucesso = primeira incorporação de um rascunho do agente.
3. **Time:** convida alguém, recebe uma proposta, comenta, incorpora. Sucesso = primeira incorporação de um rascunho de outra pessoa.
4. **Rotina:** execuções agendadas caem como rascunhos; revisar vira hábito semanal.
